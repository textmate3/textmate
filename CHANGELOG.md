# Changelog

All notable changes to TextMate are recorded here.

Format: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).
Versioning: [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).
Ordering: newest first within each section, like a feed.

## [Unreleased]

Target: **2.1.0**, the first release of the project. Version 3.0.0 is the eventual milestone, not the next release.

### Added
- `doc/tm_properties.md`, a reference for the settings file: where settings come from and in what order, the syntax, sections by scope selector or glob, variables and format string operators, and every key the settings framework reads, with the accepted values of `atomicSave`, `scmStatus` and `invisiblesMap`.
- A `Brewfile` as the one list of Homebrew dependencies, build and test alike, installed with `brew bundle`. The CI workflow and the README both defer to it instead of carrying their own copies of the list, which had already drifted apart. The MacPorts instructions are gone with it: Homebrew is the one supported way to install dependencies, and the source control tests point at the Brewfile when their tools are missing.
- Continuous integration on GitHub: every push and pull request builds the application on the macOS 26 runner and runs all test suites, including the read-only volume case. The workflow writes `local.rave` for Homebrew's Apple Silicon location, and installs Mercurial and Subversion so the source control suite exercises those drivers instead of failing for lack of them.
- A minimal built-in bundle set, so a first launch with no network still feels like TextMate. Thirteen bundles ship as archives in `Resources/SeedBundles`, 3.3 megabytes total, and a first launch extracts them before the catalog takes over: Bundle Support, HTML, JavaScript, JSON, Markdown, Property List, Ruby, Ruby on Rails, Source, Text, Themes, XML and YAML. The archives are committed to the repository so a clean checkout builds with no outside dependency, and `script/update_seed_bundles` refreshes them from the development catalog's tarballs, repacking each with its display name so first launch extraction needs nothing but tar. The catalog updates seeded bundles like any other install once it is reachable.
- Automated key event tests in the `ns` suite, `tests/t_event.mm`, replacing what the deleted `gui_key_events.mm` demo let a human eyeball. They construct synthetic `NSEvent`s and assert the exact event strings `to_s` produces, covering the modifier symbol ordering, the literal-shift rule for non-ASCII keys, and the numeric keypad flag in both modes. Every case uses a key whose translation is identical on all keyboard layouts, because the letter keys go through the active layout and would make the expectations machine-dependent.
- Local bundle catalog server at `../api.textmate3.com/`: a small Sinatra app that stands in for the legacy `api.textmate.org`. Serves `/bundles` (OpenStep ASCII plist index) and `/tarballs/:name.tbz` (prebuilt bundle archives) sourced from `../bundles/*.tmbundle/` so edits there are immediately reflected in the running app. Catalog overrides in `data/catalog.yml`.
- Script to Rule Them All development scripts:
  - `script/build` — compile TextMate via ninja (release, pass `debug` for debug)
  - `script/run` — build and launch the app
  - `script/log` — stream the macOS unified log filtered to the TextMate process, with optional AND-keyword filtering
  - `script/test` — run the framework test suites

### Changed
- `script/run` builds first and probes for the local catalog server second, so its warning is the last line before the launch rather than the first line scrolled away by the build output.
- Crash reports are logged, not uploaded. The application used to look for new crash reports every thirty seconds and post them to a `/crashes` endpoint that exists on no server: the catalog host is static files and cannot accept an upload. It now checks once at launch and writes one line to the unified log for each new report from the last week, naming the file macOS wrote, so a crash is never silent and nothing leaves the machine. The upload code, its gzip and multipart helpers, the "Crash Report Sent" notification, and the Submit to MacroMates checkbox and contact field in the Software Update preferences are gone with it. The hidden `DisableCrashReports` default still turns the logging off.
- `script/test` ends with a verdict. Ninja numbers a status line by the edges finished when an edge starts, and test edges never print a completion line, so a full green run ended one or two short of its total and looked as if a suite had been skipped. Nothing was: the count is cosmetic and the exit status is the truth, so the script now prints "All N test suites passed" or a failure line from that status.
- The HTML output scheme handler serves a page's assets only from where they can legitimately live. It used to read any readable path a page asked for. Now a request is served only if its normalized path sits under one of the bundle locations or under the document or project directory the command producing the page ran against, which keeps document-relative images in previews working. Anything else gets a 404 and a line in the log. The page comes from a command already running as the user, so this bounds accidental reach rather than defending against a hostile page: `..` cannot climb out, a root name that is a prefix of another directory does not match, and a symbolic link the user placed inside a root is honored. A bundle repository checked out elsewhere and linked into the bundles directory is handed to commands by its resolved path, so the target of every link in a bundle location's `Bundles` directory is a root as well. A page's directories stay registered after its output has arrived, because the images and scripts are requested after that. The policy is a small header with its own tests.
- The file browser's saved state is archived and restored under secure coding. The archive holds a short history of directories with scroll offsets, an index into it, and the expanded and selected URLs, and every decode now names the classes that can appear, so the unarchiver's default requirement is met instead of switched off. The file browser gains its first test target, with a round trip of exactly the shapes the encoder writes, so a decode that stops naming a class fails the suite instead of quietly losing the history at launch.
- The `file::status` tests run for real, all thirteen cases, with no privileges and no manual setup. They previously asserted only against a hand-built tree under `/tmp/x` that needed `sudo` and a read-only volume, so on every machine since they were written they printed a skip and tested nothing. The user-owned cases are built in a temporary directory by the test. The other-owner cases use files every macOS install has, `/etc/hosts`, `/etc/sudoers` and `/tmp`, since all that matters is that root owns them. The read-only volume case mounts a small disk image inside the temporary directory and runs when `TM_TEST_READ_ONLY_VOLUME=1` is set, because mounting takes a moment and is more than a default test run should do.
- The `lipo` machinery is gone from the build system. The method that merged architecture slices never ran again after the build became arm64 only, so it is renamed to `linked_executable` and reduced to handing back the single executable, and it now refuses loudly if a rave file ever declares a second architecture rather than silently building only the first.
- The bundle editor's item templates, the encoding menu's charset table and the file reference bindings are XML property lists instead of OpenStep ASCII, converted with `plutil`. Nothing reads them differently, since the loader auto-detects the format; this narrows what still depends on the ASCII parser toward the bundle editor's editing surface, which is recorded as the blocker for removing that parser.
- Notarization in the build system goes through `notarytool` instead of `altool`, which Apple shut down in late 2023. One rule submits and waits in a single call, replacing the submit rule, the polling rule and the `bin/notarize_await` helper, and it fails the build unless the returned status is Accepted. Credentials move from user name and password arguments to a keychain profile created once with `xcrun notarytool store-credentials`, whose name is now the rave `notarize` command's only argument.
- The five user interface sounds, trash, move, completion, and the recording pair, play through AppKit's `NSSound` instead of AudioToolbox, which leaves the project entirely: it was linked and imported in the prelude for these five calls alone. The rewrite also fixes a leak as old as the code: the sound cache was written through a loop copy, so every play created and leaked a fresh system sound object instead of reusing one.
- Release builds carry the production trust anchors. `SU_PUBLIC_ED_KEY` and `BUNDLE_PUBLIC_ED_KEY` in `default.rave` hold the production Ed25519 public keys for application updates and the bundle catalog, two separate pairs on purpose so a leak of one does not burn the other. The private halves live only in the maintainer's login keychain, with offline backups made at generation time. Local development continues to override both keys in `local.rave` with development pairs, so a development build never trusts production content and a release build never trusts development content.
- **BREAKING** — Bundle catalog downloads are verified with Ed25519 signatures. The index is verified against a detached signature served beside it, base64 over the exact bytes of `/bundles` at `/bundles.sig`, and every tarball against a `signature` field its index entry carries, so the expected signature is known before a download starts instead of arriving in response headers. The `signee` field and the key chain it selected from are gone: the application trusts exactly one bundle public key per build, entering through the `BUNDLE_PUBLIC_ED_KEY` build variable beside the Sparkle key, production value in `default.rave`, development override in `local.rave`. Allan Odgaard's two DSA public keys leave the binary, and with them the last SecTransform calls, which were verifying DSA over SHA-1: a clean rebuild now emits zero deprecation warnings. Verification goes through `SecKeyVerifySignature`, whose Ed25519 constants the Security framework exports but declares in no public header, so `Frameworks/network/src/ed25519.cc` resolves both at runtime with `dlsym` rather than linking them: a macOS that stops exporting them costs signature verification, with a clear error, not launch. The localhost signature bypass is deleted; the development server signs its catalog with a development keypair from `script/generate_bundle_signing_key`, so local development exercises the exact verification path production uses.
- App Transport Security is enforced, with an exception only for local destinations. The `Info.plist` carried `NSAllowsArbitraryLoads`, the blanket opt-out that upstream added in the plain-http era, which disabled the operating system's HTTPS-with-modern-TLS floor for every connection the app makes. The blanket key is replaced with `NSAllowsLocalNetworking`, which exempts only local hosts, so previewing code served from a machine on the local network keeps working over plain http while every internet destination gets transport security enforced by the system, in web views and in the application's own traffic alike. Local development needs no exception at all because the loopback interface is exempt from the policy, so dev builds keep talking to the stand-in server on `http://localhost:3000` regardless.
- **BREAKING** — Minimum deployment target raised from macOS 15 to macOS 26, the version after 15 because Apple renumbered to match the release year. Crossing it surfaced one new deprecation at two call sites, `posix_spawn_file_actions_addchdir_np`, whose replacement is the same function without the non-portable suffix: POSIX 2024 standardized it and macOS 26 ships the portable name. Both spawn paths, the command runner and `OakCommand`, now call `posix_spawn_file_actions_addchdir`. This floor also matches what the Homebrew dependencies are built for, which silences the linker's eleven notes about linking dylibs built for a newer version than the deployment target.
- **BREAKING** — Minimum deployment target raised from macOS 14 to macOS 15. Crossing this version surfaced one new deprecation, the `SCNetworkReachability` pair deprecated at macOS 14.4, whose single use was a preflight that suppressed the "Would you like to install this bundle?" suggestion when the catalog host looked unreachable. The preflight is deleted rather than ported, following the platform guidance to attempt the connection instead of predicting it: the suggestion now always appears for an unrecognized grammar, and an install attempted while offline reports the download failure it always would have.
- **BREAKING** — Minimum deployment target raised from macOS 13 to macOS 14. The floor is one `default.rave` variable and flows into the compiler, the linker, the asset compiler and `Info.plist`. Crossing 14 surfaced three calls to interfaces deprecated at exactly that version, every one already inert: two `bezeled` setters on progress indicators, which macOS has ignored since 10.15, and the ignore-other-applications activation option, which macOS 14 makes a no-op because activation is cooperative and the system decides whether the terminal actually comes forward. The two setters are deleted and the activation passes no options. This raise also crosses the availability threshold for `kSecKeyAlgorithmEdDSASignatureMessageEd25519SHA512`, macOS 14 and later, which the Ed25519 bundle catalog signing needs.
- The production programming interface host is `https://api.textmate3.com`: the `REST_API` build default that the bundle catalog, the updater sources and the crash reporter all compile against, and the `SUFeedURL` default beside it. The legacy `api.textmate.org` appears nowhere in the build. Local builds continue to override both to `http://localhost:3000`.
- **BREAKING** — Application updates go through Sparkle 2.9.6, vendored as a prebuilt framework at `vendor/Sparkle` and embedded in the application. The bespoke update engine is deleted: its check and install machinery, the release, beta and canary channel plumbing, the Check for Test Build menu item, and the channel picker in the Software Update preferences pane, which now drives Sparkle's own defaults. The feed URL and the Ed25519 public key that updates must be signed with enter `Info.plist` as `SUFeedURL` and `SUPublicEDKey` from build variables, so local development points both at the stand-in server on localhost with a development key while release builds carry the production pair. The `SoftwareUpdate` framework remains for what the bundle system uses, `OakDownloadManager` and `OakCompareVersionStrings`, so the five deprecated Security transform calls in the download manager now belong to the bundle catalog signing work rather than to the update system. `api.textmate3.com` gains `/appcast.xml` and `/releases/`, and its `script/appcast` packages a built application, signs it, and regenerates the feed, which makes the whole update path exercisable offline: check, download, signature verification, install and relaunch, all against localhost.
- `rave` copies a symbolic link as a link rather than following it, and treats a symlinked directory as a leaf instead of recursing into it. This is what allows an embedded prebuilt framework, whose `Versions` layout is built from symbolic links, to survive the trip into the application bundle with a valid code signature.
- Onigmo, the regular expression engine, is pinned to the `textmate3/Onigmo` fork's `main` rather than the `Onigmo-6.2.0` release tag, picking up upstream fixes that exist in no release because upstream has cut none since 2019: an out-of-bounds read in character class parsing, a stack overflow on deeply nested repetition, a crash in `onig_error_code_to_str`, a crash in `onig_new`, Unicode 12.1 tables, and Ruby's rewritten `st` hash table. On top of that sits one fork-authored commit giving the `st` function pointers full prototypes, which C23 requires and which clears the last eight compiler warnings from Onigmo sources. `doc/ONIGMO.md` describes the arrangement and the procedure for taking upstream changes.
- The document type icons are part of this repository rather than a submodule: 56 files at `Applications/TextMate/icons`, unchanged in content and path. Nothing outside the application consumes them, which is the test the remaining submodules pass and this one failed — what stays a submodule is the three vendored third-party forks, each with a real upstream. The icons' standalone history is in the `textmate3/document-icons` repository, which is archived.
- The dialog plug-in's source is part of this repository rather than a submodule. `PlugIns/dialog` holds the same 36 files at the same paths, the build is unchanged, and `Dialog2.tmplugin` ships exactly as before, so the only thing that moves is the bookkeeping: a change spanning the plug-in and the application lands as one commit instead of a commit, a push, a pointer bump and a second push, and there is no pointer that can reference an unpushed commit. This follows what was done for the commit window, whose source lives at `Frameworks/CommitWindow`. The plug-in's independent history stays in the `textmate3/dialog` repository, which is archived. The other four submodules remain: three vendored third-party forks and the shared document icons, all of which have a life outside this repository in a way the dialog plug-in did not.
- `$DIALOG` talks to the `Dialog2` plug-in over a UNIX domain socket rather than Distributed Objects. The socket is at `$TMPDIR/textmate-dialog-<pid>.sock` and the plug-in exports it as `DIALOG_SOCKET_PATH`, replacing `DIALOG_PORT_NAME` which named a Mach port. Bundles are unaffected: they invoke `$DIALOG` and exchange data over the three FIFOs the tool creates, which is unchanged. The tool now waits for the editor to acknowledge a request before opening those FIFOs, because opening one blocks until the other end does, so a request that never arrived used to hang with nothing reported.
- The commit window talks to `CommitWindowTool` over a UNIX domain socket rather than Distributed Objects, removing six deprecated `NSConnection` uses. The socket lives at `$TMPDIR/textmate-commit-<pid>.sock`, keyed by the editor's process id so a tool always reaches the editor that launched it, and the path is derived in one place instead of a service name being formatted separately in the framework and the tool. Nothing bundle-visible changes: the four version control bundles that use the window run the tool as a subprocess and read its standard output, so the transport was never part of their contract.

  The tool no longer vends anything of its own. Distributed Objects needed a second connection in the opposite direction for the reply, which is what the tool's own listener, its port registration and its delayed teardown existed for. A socket is already bidirectional, so the tool writes its request, half-closes to mark the end of it, and blocks reading the same connection until the sheet is dismissed.

  `NSXPCConnection` is not usable here, despite being what the deprecation notice recommends. `NSXPCListener` does not register a Mach service, it checks out one launchd already holds, so a name has to be declared ahead of time in a launchd property list. That rules out naming a service after a process id, which is how a tool finds its own editor. `mate` has always used a UNIX socket for the same job.

- The tab bar's drag support names the file URL pasteboard type as `NSPasteboardTypeFileURL` rather than casting the deprecated `kUTTypeFileURL`. Both are the string `public.file-url`, verified rather than assumed, so nothing about the drag behaviour changes. This finishes the pasteboard sweep below, which had left the tab bar behind. No `kUTType` constant survives anywhere in the project.
- The `dialog` plug-in's completion pop-up lost its last two availability guards, `@available(macos 11.0, *)` around the plain table view style and `@available(macos 10.14, *)` around the vibrancy backing. Both are unconditionally true at a macOS 13 floor, and the second carried an `else` branch that skipped the `NSVisualEffectView` entirely, which no supported system could ever have reached. There is now no availability check for a release below the deployment target anywhere in the project.
- `Frameworks/scm` stopped linking `Security`, which it never used. No `Sec` symbol appears in its sources and its compiled objects have no undefined `Sec` references. Carbon was the other half of that line and went earlier, so the target now declares no frameworks of its own and takes what it needs through `require`.
- `Shared/PCH/prelude-mac.h` no longer imports the Carbon umbrella into every translation unit in the project. Only two files genuinely need it and they now say so: `Frameworks/ns/src/ns.mm` for the `kVK_` virtual key codes, and `Frameworks/OakAppKit/src/OakKeyEquivalentView.mm` for `PushSymbolicHotKeyMode`. Neither can narrow further, because HIToolbox's subframework headers cannot be included on their own. `ns` needs the header but not the library, since the key codes are compile-time constants, so it still links Cocoa and nothing else. Removing the umbrella exposed three headers that used CoreGraphics or CoreText types without including either and had been compiling only because Carbon dragged both in: `Frameworks/theme/src/theme.h`, which names `CTFontRef` and `CGColorRef` in its public interface, `Frameworks/cf/src/cgrect.h`, and `Frameworks/theme/tests/CGColorRefToString.h`. All three now include what they use. The last two surfaced only in the test binaries, because those are pure C++ translation units with no AppKit in scope, so the application target alone would not have caught them.
- The Open With menu asks `NSWorkspace` which applications can open a document, through `URLsForApplicationsToOpenURL:`, rather than calling `LSCopyApplicationURLsForURL` with `kLSRolesAll`. The header marks the old call `API_DEPRECATED` with `API_TO_BE_DEPRECATED` as the version, which is why it emitted no warning yet and would have begun to the moment Apple named a release. The result is the same set of applications, and the menu drops it into a set immediately, so the two calls' different ordering guarantees do not matter. The `CFBridgingRelease` and the bridged cast go with it.
- `Frameworks/OakFilterList` and `Frameworks/scm` stopped linking Carbon. Neither contains a Carbon-era symbol, which their compiled objects confirm: between them there is not one LaunchServices, HIToolbox or Apple Event reference. That leaves a single Carbon link in the project, in `Frameworks/OakAppKit`, which earns it with `PushSymbolicHotKeyMode` in the shortcut recorder. That call is undeprecated and has no AppKit equivalent, so it stays. This is about linking only: `Shared/PCH/prelude-mac.h` still imports the Carbon umbrella into every translation unit, which is a separate piece of coupling.
- `path::home()` falls back to the `HOME` environment variable when `getpwuid` returns nothing readable, instead of putting up the missing home folder alert and blocking. `getpwuid` is still tried first, so the normal case is unchanged, and `HOME` is only consulted when it comes back empty. This matters because `HOME` is set by launchd at login and so does not need a directory services lookup to succeed at the moment TextMate asks, which is the exact failure the alert exists for. The alert is still the last resort if neither source names a readable folder.
- The missing home folder alert lost its Show Radar Entry button. It linked to an Open Radar page for a bug filed in 2011 and marked a duplicate of one that was never resolved, so the only thing it ever offered was reading about the problem. Removing it deletes the deprecated `LSOpenURLsWithRole` call behind it, and with it the last Carbon-era symbol anywhere in the `io` framework, so `Frameworks/io/default.rave` no longer links Carbon at all. The alert's message is also honest now: it used to append `strerror(errno)`, but `getpwuid` does not set `errno` when it simply has no record to return, so in exactly the situation the alert exists for it read "Undefined error: 0".
- The tooltip window in the `dialog` plug-in moved from the legacy `WebView` to `WKWebView`, which was the last legacy WebKit use anywhere in the tree. It is a separate repository, so the change arrives as a submodule pointer bump. Three things had to move. The `WebPreferences` object has no counterpart, so the editor font settings are written into the document's own style sheet, which preserves the old split where `<pre>` content renders in WebKit's own fixed font rather than the editor font, since `fixedFontFamily` was never set. Measuring the rendered content went from a synchronous `evaluateWebScript:` to an `evaluateJavaScript:completionHandler:` callback, because the script now runs in another process. That in turn means the anchor point and the target screen are captured before the web view is grown for layout rather than after, and the growth happens ahead of the load so the measurement cannot race the resize. If the measuring script fails, the tooltip logs and closes, where before it would have shown a zero by zero window.
- Two more deprecated calls in the `dialog` plug-in are gone. The color value transformer serializes through `colorUsingColorSpace:` with the generic RGB space, which is the same space `NSCalibratedRGBColorSpace` named. The file panel builds `UTType` objects for `allowedContentTypes` instead of handing raw strings to `setAllowedFileTypes:`, so the `--allowedFileTypes` option still accepts both filename extensions and uniform type identifiers, and an entry matching neither now warns on standard error rather than being dropped in silence.
- New-command default in the Bundle Editor (`Frameworks/BundleEditor/templates/Command.plist` and `Drag Command.plist`) — shebang now `#!/usr/bin/env ruby -w`, from `ruby18 -wKU` and `ruby18 -KU`. The interpreter was canonicalized first and the Ruby 1.8 `-K U` encoding flag dropped afterwards, once it turned out that current Ruby warns `-K is specified; it is for 1.8 compatibility and may cause odd behavior`. The same flag was cleared from `bin/show_log` and from 16 files across six bundles, all of them property list command bodies rather than standalone Ruby files, which is why an earlier sweep did not see them.
- The proxy credential lookup uses the `SecItem` family instead of the deprecated `SecKeychainItem` calls. The query was already modern; only the second half was not, asking `SecItemCopyMatching` for opaque handles and then interrogating each one through `SecKeychainItemCopyAttributesAndData` with a CSSM format descriptor, which was the tree's last CSSM reference and emitted no warning of its own. The lookup runs in two passes, because `kSecReturnData` cannot be combined with `kSecMatchLimitAll`: together they fail with `errSecParam`. Enumerating accounts first and fetching one password at a time also preserves the previous behavior of moving on when a particular item cannot be read, which is what happens when an item's access control denies us. This only runs on a machine behind an authenticating HTTP or SOCKS proxy.
- The `authorization` framework declares the `Security` framework it uses. The `io` framework linked it without using a single `Sec` symbol, and `authorization` and the privileged tool were getting it transitively from there, so dropping the unearned link broke their build until it was declared where it is earned.
- The last two always-true availability annotations are gone, both `API_AVAILABLE(macos(10.13))` on accessibility rotor methods. An earlier sweep missed them because it searched for `macosx(10.` while these spell it `macos(10.`.
- The HTML output subsystem moved from the legacy `WebView` to `WKWebView`, which removes every remaining legacy WebKit use in the application. `WebView` is deprecated since macOS 10.14 but still present in the macOS 26 software development kit, so this was not a compile deadline; the reason to do it was that the unstyled output bug below has no other fix. Along the way: the `NSURLProtocol` subclass that served command output became a `WKURLSchemeHandler`, and because protocol properties do not survive the crossing into the content process the output pipe moved to a registry keyed by URL; progress reporting moved from three notifications to key value observing on `estimatedProgress`; the JavaScript alert, confirm and file panel callbacks gained completion handlers, since the content process cannot be blocked waiting for a modal answer; and find, selection and view source became asynchronous, which also retired the encoding branches view source used to carry, because markup now arrives already decoded.
- **BREAKING for bundle authors** — `TextMate.system()` in HTML output is asynchronous. The old bridge handed the page a live Objective-C object that could be called synchronously; `WKWebView` runs the page in another process and offers no synchronous path. Passing a callback works exactly as before, and `cancel`, `write`, `close`, `onreadoutput` and `onreaderror` still reach the running command, since none of those needed the result. Only reading `outputString` or `errorString` directly off the return value cannot work, because both require the command to have finished. That case throws an error naming the property and showing both replacements, rather than yielding `undefined` and rendering wrong output silently. The bridge itself is a user script registered on the web view configuration, since the window-object hook it used to arrive through does not exist.
- Auto-scrolling a streaming command's output is now done inside the page with a `MutationObserver` that re-pins to the bottom when the viewport was already there. The previous implementation observed frame-change notifications on the web view's document view, which no longer exists from the application's side.
- Page errors in HTML output windows are reported to the unified log: window error events, unhandled promise rejections, and `console.error` and `console.warn`. The legacy view had an undocumented hook for this. It matters more than it did, because a bundle that wraps a bridge call in `try`/`catch` and discards the result would otherwise fail with no trace anywhere.
- The selection color in the Go to File and Go to Symbol windows uses `selectedContentBackgroundColor` instead of the deprecated `alternateSelectedControlColor`.
- File icons throughout the interface come from `NSWorkspace.iconForContentType:` with UniformTypeIdentifiers rather than the deprecated `iconForFileType:` and its HFS type codes. Eleven call sites across the tab overflow menu, file browser, bundle editor, preferences and menus. Extension lookups go through a new `NSWorkspace.iconForFilenameExtension:` helper, because `UTType.typeWithFilenameExtension:` does not resolve package types such as `tmbundle` and returns a dynamic placeholder with no icon; the helper retries as a package type whenever the plain lookup yields an undeclared type.
- Pasteboard types moved to their UniformTypeIdentifiers-era replacements: `NSFilenamesPboardType` to `NSPasteboardTypeFileURL`, `NSURLPboardType` to `NSPasteboardTypeURL`, `NSColorPboardType` to `NSPasteboardTypeColor`, `kUTTypeURL` to `UTTypeURL.identifier`, and the `NSGeneralPboard` and `NSFindPboard` names to `NSPasteboardNameGeneral` and `NSPasteboardNameFind`. The old and new file constants differ in shape rather than spelling: one property list item holding an array of paths becomes one item per file, so every read site moved from `propertyListForType:` to `readObjectsForClasses:` and works in `NSURL`.
- `vfork` replaced with `posix_spawn` in the four sites that are actually compiled: the `mate` command line tool, the privileged helper installer, bundle command execution, and `OakCommand`. `POSIX_SPAWN_CLOEXEC_DEFAULT` replaces a loop closing every inherited descriptor, `POSIX_SPAWN_SETSIGDEF` replaces resetting four signal handlers by hand, and a process group of zero replaces `setpgid`. The working directory needed care: the forked code called `chdir` in the child and let failure pass, while `posix_spawn` fails the entire spawn when any file action fails, so the directory change is now requested only when the directory exists. A command whose working directory has been deleted still runs, in the inherited directory, as before.
- Application launching uses `NSWorkspace.openURLs:withApplicationAtURL:configuration:completionHandler:` instead of the deprecated `launchApplication:` family, which also let an AppleScript workaround for opening several files at once be deleted.
- The vendored Onigmo regular expression engine updated from 5.15.0 to 6.2.0, a clean fast forward of 585 upstream commits. Onigmo 6 renamed its umbrella header from `oniguruma.h` to `onigmo.h`, spelled out the encoding source file names, and moved the generated Unicode tables to a directory it expects on the include path. It also derives the width of `st_data_t` by comparing `SIZEOF_LONG` and `SIZEOF_LONG_LONG` against `SIZEOF_VOIDP`, and an undefined macro reads as zero, so the hand maintained `config.h` had to learn two sizes it never previously needed.
- Every variable length array replaced with a `std::vector` or a fixed bound, removing all eleven `-Wvla-cxx-extension` warnings. The fuzzy match ranker keeps its `matrix[i][j]` indexing through a vector of row pointers, so the matching walk is untouched.
- `NSKeyedArchiver` and `NSKeyedUnarchiver` use the secure coding initialisers rather than the deprecated whole-object convenience methods.
- `mktemp` replaced with `mkstemp`, which is a real security fix rather than a warning silencing: the old call returned a name, leaving a window between the check and the create, while the new one returns a descriptor to a file that already exists.
- `commitEditing` is declared where it is implemented, in the bundle editor and the find window, so the selector resolves against the local declaration rather than the deprecated one.
- File system watching moved from run loop scheduling to dispatch queues, replacing the deprecated `FSEventStreamScheduleWithRunLoop` in the file browser, the `io` framework, and source control status. Callbacks are delivered on the main queue, which preserves the previous threading and timing. The two `FSEventStreamFlushSync` calls were removed, since a synchronous flush cannot be serviced by the queue that is blocked calling it.
- The preferences window remembers its position and selected pane under new user defaults keys, `preferencesWindowFrameTopLeft` and `preferencesSelectedPane`. They were previously named after MASPreferences, a library the app stopped using years ago when the window was reimplemented natively, and the stale names implied a dependency that does not exist. Upgrading users open the preferences window once at its default position on the first pane, after which it remembers again as before.
- **BREAKING** — sparsehash is no longer a build dependency. Its sole use, the theme style cache, is a `std::unordered_map` now (`scope_t` already had a `std::hash` specialization), and the README's prerequisite lists shrink by one package.

The precompiled header no longer includes `boost/variant.hpp`; Boost's remaining use is `boost/crc.hpp`. All sixteen framework test suites pass.
- **BREAKING** — Minimum deployment target raised from macOS 10.12 to macOS 13.
- C++ standard raised from `c++2a` to `c++23`. The stricter standard surfaced and forced the fix of a latent crash (see Fixed, `selection_t`).

A full build's warning count dropped from the mid five hundreds to double digits, making the remaining real deprecation worklist readable.

### Removed
- `local-orig.rave` and its two helper scripts, `bin/update_changes` and `bin/extract_changes`. The file was a snapshot of the original maintainer's machine-local build overrides and release recipe: Nix paths, DSA release signing, the retired `api.textmate.org` upload, all superseded by Sparkle, the signed catalog and `notarytool`. Nothing loaded it, and the release pipeline for the first release gets designed fresh rather than grown from it.
- The ODB Editor Suite, the BBEdit-era Apple Events protocol behind "edit in TextMate" integrations like QuickCursor: an external application could hand a file over and be notified on save and close. Opening files through the open-file delegate methods no longer inspects the current Apple Event for ODB parameters. Modern integrations use the `txmt:` URL scheme, which stays.
- The Intel slice from the release build template. `local-orig.rave` now builds arm64 alone, and the debug configuration stops shelling out to `uname -m` for an architecture the project no longer targets. The `lipo` merge machinery in `rave` stays, because it already passes a single-architecture build through untouched. The unused `machine/byte_order.h` prelude import goes with this cleanup, confirmed dead by the same audit.
- The last Carbon link. Recording a keyboard shortcut no longer calls `PushSymbolicHotKeyMode` to stop the system from swallowing reserved combinations, so a shortcut that collides with a system hot key cannot be captured in the recorder: the system acts on it instead. That is the accepted cost of dropping the one interface that had no AppKit replacement, and the workaround for an affected user is turning the colliding system hot key off while recording. With that gone, Carbon vanishes from the project completely: the `kVK_` virtual key code names the event machinery uses now come from `Frameworks/ns/src/virtual_key_codes.h`, fifty five values copied from the software development kit, safe to copy because they identify physical key positions frozen since the original Macintosh keyboards. The stale `-framework Carbon` in the suggested `TM_CXX_FLAGS` variable in Preferences goes too. No source file, build file, or binary mentions Carbon.
- The `DefaultBundles.tbz` first-launch seed archive, which only the deleted `bl` could build: the build ran `bl` against the catalog to pre-install the mandatory and default bundles into an archive extracted on first launch. A first launch now extracts the minimal seed set described under Added and installs the rest from the catalog as soon as it is reachable, the exact path the bundle manager already exercises on every index refresh. The old tarball extractor goes too, which reduces the `network` framework to the Ed25519 verifier alone.
- `bl`, the command line bundle manager, and the entire parallel download stack that existed only to serve it: the `updater` framework, and the `network` framework's curl machinery, tarball downloader, streaming signature filter, proxy resolution and user agent. The application never invoked `bl` and no build ever shipped it; the in-application bundle manager uses its own Objective-C path, which now stands as the one place catalog behavior lives. The `network` framework shrinks to the Ed25519 verifier and the tarball extractor, curl leaves the project entirely, and the SystemConfiguration import leaves the prelude with proxy resolution, its last user. A terminal bundle manager remains a future direction, designed fresh against the marketplace rather than grown from this stack.
- The `bin/CxxTest` submodule, along with the four `gui_*.mm` files that were its only consumers and the `cxx_tests` build command that fed them. The real test harness is `bin/gen_test`, a first-party Ruby script that scans `tests/t_*.cc` for free `test_` functions and generates each suite's runner, and it never involved CxxTest. The `cxx_tests` command was parsed by `rave` into target data that no rule generator read, so the four files have been unbuildable dead code: not compiled by any target, not run by `script/test`. They were interactive demo harnesses rather than tests, spinning up a one-window app for a human to poke, gated behind a `GUI_TESTS` environment variable. Their four scenarios, key glyph rendering, layout integrity under interactive editing, the pop-out animation, and dictionary popover protocol conformance, are recorded as future harness material rather than kept as broken files. The editor configuration lines excluding the submodule from search, and the `attr.test.cxxtest` scope attribute that activated CxxTest snippets, are gone with it. One submodule remains, the Onigmo fork. The CxxTest fork's history stays in the `textmate3/cxxtest` repository, which is archived.
- The `TMSigningKeys` dictionary in `Info.plist`, which carried one of Allan Odgaard's DSA public keys for the bespoke update engine. Its reader went with that engine during the Sparkle adoption, leaving the key as unread data, and the Ed25519 catalog signing removed the last code that could have wanted it.

The migration was verified against a real 414-project database: every row converted.

### Known issues
- `TextMate.system()` reading `outputString` or `errorString` synchronously throws, by design, but a bundle that catches the exception and discards it still fails quietly. `git.tmbundle`'s `Support/resource/rb_gateway.js` does exactly this in `ENV`, `gateway_command` and `dispatch`, which is why Git Config appears to accept an edit and does not save it. The thrown message now reaches the unified log even when the page swallows it.

### Fixed
- After a command replaces the current line, the caret lands where it was by character rather than by byte. It used to be carried by byte offset, so a command that turned `a` into `á`, which is one byte longer, left the caret before the new character instead of after it, and typing continued on the wrong side.
- Bundle commands whose shebang asks for `ruby`, through `/usr/bin/env` or by path, run on the Ruby that `TM_RUBY` names when it is set to an absolute path, from Preferences → Variables or a `.tm_properties` file. Only Command-R in the Ruby bundle honored it before, while every other Ruby command resolved through the bare `PATH` the application hands commands to the system Ruby 2.6.
- The caret steps by grapheme cluster instead of code point. A family emoji joined from four people, a flag built from tag characters, or an `e` followed by a combining accent each took several arrow presses to cross while the glyph never changed. Left and right movement, and the selections extended from it, now cross a whole cluster at a time, in the layout's row stepping and in the fallback used without a layout, through a small helper in the text framework built on Core Foundation's composed character ranges. Line ends are still crossed one newline at a time, and text that is not valid UTF-8 falls back to stepping by code point.
- HTML output pages get a command's whole output from `TextMate.system` again. The bridge streamed each read to the page and then dropped it from its buffer, so the promise resolved with only the last kilobyte, which is why the git bundle's diff toggles showed a single line of a multi-file diff.
- A command started from an HTML output page no longer hangs the application when it forwards its standard input, which `tm_dialog2 x-insert` does. The page held the command's input pipe open for ever, the dialog tool forwarded that pipe, and the dialog plug-in read it to end of file on the main thread. The input now closes on its own once the script task that started the command has finished, unless that task wrote to it. The Unicode bundle's pickers insert again.
- The gutter clips its background, selection and border fills to its own bounds rather than its frame. The frame is expressed in the superview's coordinate space and the drawing happens in the view's own, so intersecting the dirty rectangle with the frame was a category error that only worked because the two rectangles coincide while the frame origin is zero. No visible change today; it stops being correct the moment the gutter is placed at a non-zero origin.
- Gutter line numbers, bookmarks and folding arrows render again. The one point divider between the gutter and the text is an `OakBackgroundFillView`, and its color fill covered the dirty rectangle it was handed rather than its own bounds. Since macOS 14 views no longer clip drawing to their bounds by default, and macOS 26 hands `drawRect:` dirty rectangles far wider than the view, so the divider painted its color across the whole gutter beside it. That is why the gutter looked like a translucent screen over the document in every theme: the divider color is the theme foreground softened. The fill is now clipped to the view's bounds, which also covers every other divider and fill view built from that class. The same overdraw was the commit window bug: the sheet's message editor carries that divider, and it painted across the sheet, hiding the Previous Commit Messages popup, the file list, and the Cancel and Commit buttons. Verified by reproducing the broken sheet on the commit before the fix and the whole sheet after it.
- The bundle index no longer downloads twice at launch. The background scheduler's first fire could land at the same moment as the immediate fetch, racing two install waves over the same bundle objects, which the logs showed updating the same bundles twice within a second and which is the suspected origin of the corrupt index path that once deleted the managed bundles directory. Update cycles are now serialized on the main thread: callers arriving while a cycle runs are queued and receive that cycle's result instead of starting a second download. Verified live: one index fetch per launch and no duplicated bundle updates.
- Live spelling underlines misspelled words again. The synchronous parse in `wait_for_repair` disables spell checking for its duration, a macOS 10.12-era workaround for a dispatch thread limit, but the disabled check still erased the existing misspellings for every range it parsed and nothing ever rechecked afterward. Since the editor takes this path constantly, the underlines were wiped as fast as they could appear. The parsed span now gets one recheck after checking is re-enabled, which keeps the original protection, since the per-line parse loop still never touches the spell checker. The four spelling tests this had forced off are back on.
- Two failure modes in the command runner's wait for detached HTML commands, one losing output and one hanging. The wait stopped its run loop from another thread, which could either abandon the queued completion block, dropping the standard error text that gets appended to the HTML output after a successful command, or fire before the loop started and be lost entirely, leaving the wait blocked forever. The end-of-wait signal now queues onto the run loop itself, behind the completion block it must not overtake, and the wait polls with a timeout so no wakeup can be lost. The two HTML output tests this had forced off are back on, and the command suite passed ten consecutive runs with them.
- Installing a bundle whose local index entry carries a corrupt path can no longer destroy the managed bundles directory. The installer replaces whatever exists at its destination, and a poisoned entry once resolved a bundle's destination to the install directory itself, so one install deleted every installed bundle. Three guards close this at every layer: the local index refuses to save an entry whose path escapes `Bundles/`, refuses to load one, and the installer falls back to the destination derived from the bundle's name whenever the recorded path points outside the bundles directory.
- `rave`'s stale output cleanup removes directories and dangling symbolic links, not only plain files. Bundle outputs such as `.tmplugin` and `.appex` are directories, and `File.unlink` raises on those, so a target that stopped being built survived in the application bundle as unsigned nested code and `codesign` refused the whole application with "bundle format unrecognized" — an error that names nothing about its cause. The cleanup now uses `FileUtils.rm_rf`, and checks `File.symlink?` alongside `File.exist?` so a link pointing at nothing is still removed, which resolves the long-standing FIXME about symbolic links in that loop.
- `Frameworks/network/src/filter_check_signature.{h,cc}` — added `check_signature_t::skip_validation()` setter. Callers in `Frameworks/updater/src/download.cc` (`download_etag`) and `Frameworks/network/src/download_tbz.cc` (`download_tbz`) detect URLs that point at `localhost` or `127.0.0.1` and disable signature checking on those downloads. This lets the dev loop pull `/bundles` and bundle tarballs from the local `api.textmate3.com` Sinatra server (which doesn't sign responses) without compromising the signed path used against the real `api.textmate.org`. Will be reversed when a proper signing key is added

The cause was that **a page served from a custom scheme cannot load `file://` subresources**, and the legacy `WebView` would not even request them through the custom scheme, refusing the load before `NSURLProtocol` was consulted, so nothing was logged and nothing reached a console. `WKWebView` will serve them through the same scheme the page came from, so the fix required the migration above and could not have been done without it. Two halves: the scheme handler serves the page's own assets from disk, and `bundle-support.tmbundle` requests them through `x-txmt-filehandle://` rather than `file://`. The theme dropdown in output windows, which was blocked behind the same issue, works again.
- Dragging a file from the Finder into the editor silently did nothing. At runtime `to_s(NSString*)` casts to `CFStringRef` and calls `CFStringGetLength`, which for an `NSURL` is undefined rather than fatal, so the drop failed quietly instead of loudly. The parameter is now typed `NSArray<NSString*>*`.
